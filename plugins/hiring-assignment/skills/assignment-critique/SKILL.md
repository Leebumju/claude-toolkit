# 제출물 적대적 평가

**평가는 내가 하지 않는다.** 이 저장소를 만든 세션이 스스로를 평가하면 방어적으로 나온다.
설계 이유를 알고 있으니 모든 선택이 정당해 보이고, 채점자가 실제로 겪을 마찰이 안 보인다.

그래서 **이 대화를 물려받지 않는 새 세션**에 넘긴다.

---

## 어떻게 쓰나 — 실제 흐름

```
사용자: "이거 붙을 수준이야?"  (제출 2시간 전)
   │
   ├─ 1단계  무엇을 넘길지 정한다 ─────────────────▶ 사용자가 확인
   │          저장소 경로 · 요구사항 원문 ·            ■ 여기서 멈춘다
   │          회사 프로필 셋뿐                         프로필이 없으면 기본 가중치로
   │          내 설명·사정은 넣지 않는다                돈다는 것을 먼저 말한다
   │
   ├─ 2단계  `Agent` 로 `assignment-critic` 을 띄운다
   │          `fork` 를 쓰지 않는다 — 이 대화를
   │          물려받으면 편향이 그대로 넘어간다
   │          시간이 걸린다. 기다리는 동안 미리
   │          고치기 시작하지 않는다
   │
   ├─ 3단계  결과를 그대로 전달한다 ───────────────▶ 사용자가 원문을 읽는다
   │          판정과 탈락 사유를 먼저                  ■ 여기서 멈춘다
   │          요약·완충·변호를 붙이지 않는다            무엇을 고칠지는 사용자가 정한다
   │
   └─ 4단계  고칠 것을 남은 시간으로 나눈다 ───────▶ 사용자가 배분을 확정
              지금 고칠 것 / README 로 옮길 것 /       ■ 승인 전에 코드를 건드리지 않는다
              안 할 것
```

**멈추는 지점이 셋이다.** 무엇을 넘길지 확인받기 전, **평가 결과를 전달한 직후**,
그리고 수정 범위를 확정하기 전.

3단계에서 멈추는 것이 이 스킬의 존재 이유다. 결과를 요약하거나 순서를 바꿔 완충하는 순간
편향을 없애려고 외부 세션에 넘긴 의미가 사라진다. **원문을 먼저 놓고, 무엇을 고칠지는
사용자가 정한다.**

1단계에서 멈추는 이유는 **프로필 유무가 판정 기준을 바꾸기 때문**이다. `profiles/<회사>.md`
없이 돌리면 에이전트가 기본 가중치를 쓴다. 그 사실을 돌린 뒤에 말하면 판정을 이미 읽은
상태가 되므로, 띄우기 전에 말한다.

### 평가 결과는 파일로 남긴다 — 재개 지점

`.claude/assignment-critique/<과제이름>.md` 에 적는다. **추적되는 경로에 두지 않는다** —
평가 기록이 제출물에 섞이면 그 자체가 감점 항목이 된다.

평가 에이전트는 시간이 걸리고, 그 사이에 대화가 끊길 수 있다. 끊기면 **판정 원문**과
**무엇을 고치기로 했는지** 가 사라지고, 마감 직전에 다시 띄우게 된다. 다시 띄우면 판정이
같게 나오지 않는다. 기억으로 이어가지 않는다.

```markdown
## 돌린 조건
저장소 경로 / 회사 프로필(파일명, 없으면 "없음 — 기본 가중치") /
요구사항 원문 넘겼는지 / 돌린 시각 / 제출 마감 시각

## 판정 (에이전트 원문)
> 붙여넣기. 줄여 쓰거나 순서를 바꾸지 않는다

## 지적 항목과 배분
| 지적 | 사용자 판단 | 상태 |
|---|---|---|
| 요구사항 중 실패 케이스 처리 없음 | 지금 고친다 | 진행 중  ← 여기서 멈췄다 |
| 테스트가 해피 패스만 | README 로 옮긴다 | 문장 작성 |
| 모듈 경계가 없다 | 안 한다 (남은 시간에 못 함) | — |

## 두 번째로 돌렸다면
새 에이전트로 띄운 시각. 앞 판정 파일은 지우지 않고 함께 남긴다
```

### 다른 절차로 넘기는 지점

**아래는 지켜야 할 원칙이고, 같은 이름의 스킬은 그 원칙을 절차로 풀어놓은 것이다.**
스킬이 설치돼 있으면 `Skill` 로 부르고, **없으면 원칙만 지키고 그대로 진행한다.**

| 이런 게 나오면 | 지킬 원칙 | 절차가 있는 스킬 |
|---|---|---|
| 지적을 반영한 뒤 제출 점검이 남았다 | 고친 뒤에 clean clone 검증을 한 번 더 한다. 순서가 반대면 고친 것이 검증되지 않는다 | `assignment-submit` |
| "구조를 다시 짜라" 는 지적을 남은 시간에 받아야 한다 | 남은 시간에 전부 갈아엎지 않는다. 옮길 범위를 먼저 자른다 | `ios-modernize:legacy-port` |
| "느리다 · 비효율" 처럼 수치로 다투는 지적이다 | 체감으로 고치지 않는다. 재고 고치고 다시 잰다 | `ios-measure:measure-ios` |

같은 플러그인 안의 스킬은 이름 그대로, 다른 플러그인의 스킬은 `플러그인:스킬` 형식이다.
**호출에 실패하면 원칙만 적용하고 계속 간다.** 마감 직전에 스킬을 찾느라 시간을 쓰지 않는다.

## 절차

### 1. 무엇을 넘길지 정한다

에이전트에게 주는 것은 **저장소 경로 · 과제 요구사항 원문 · 회사 프로필** 셋뿐이다.

회사 프로필은 `profiles/<회사>.md` 에 있다. 없으면 `profiles/_template.md` 를 복사해
**과제 안내를 읽는 그 자리에서** 채운다. 나중에 채우면 기억으로 쓰게 되고 추정이 확정으로 섞인다.
프로필이 없는 채로 돌려도 된다 — 에이전트가 기본 가중치를 쓰고 그 사실을 보고서에 적는다.

**프로필에 내 사정을 적지 않는다.** 프로필은 그 회사가 무엇을 보는지에 대한 기록이고,
내가 무엇을 잘했는지는 거기 들어갈 자리가 없다.

**절대 넘기지 않는 것:**

- 왜 그렇게 설계했는지에 대한 내 설명
- 무엇을 검증했는지, 무엇이 잘 됐는지
- 이게 템플릿 기반이라는 사정, 시간이 없었다는 사정
- "이 부분 어떻게 보이냐" 같은 유도 질문

이걸 넘기는 순간 평가가 아니라 동의 요청이 된다. **채점자는 그런 걸 못 듣는다.**

### 2. `Agent` 툴로 `assignment-critic` 을 띄운다

`subagent_type: "assignment-critic"`. **`fork` 를 쓰지 않는다** — fork 는 이 대화를
그대로 물려받아서 편향을 없애려는 목적이 무너진다.

프롬프트는 이 정도로 짧게 유지한다.

```
<profiles/<회사>.md 내용 전체 — 없으면 이 줄을 뺀다>

---
저장소: <경로>
과제 요구사항: <원문 또는 "주어지지 않음">
제출물로 평가해라.
```

### 3. 결과를 그대로 전달한다

**변호하지 않는다.** 지적이 틀렸다고 느껴도 먼저 그대로 옮긴다. 반박은 사용자가 물었을 때만,
그리고 근거를 확인한 뒤에만 한다.

특히 이런 반응을 하지 않는다.

- "그건 의도한 겁니다"
- "시간이 없어서 그렇습니다"
- "그건 템플릿이라 그렇습니다"

이 세 문장은 채점자 앞에서 쓸 수 없는 말이다. 여기서도 쓰지 않는다.

전달할 때는 **판정과 탈락 사유를 먼저** 놓는다. 통과 요소를 앞에 놓아 완충하지 않는다.

### 4. 고칠 것을 남은 시간으로 나눈다

지적을 받은 뒤 사용자와 정하는 것은 이것이다.

- **지금 고칠 것** — 제출 차단급. 남은 시간 안에 확실히 끝나는 것
- **README 로 옮길 것** — 못 고치는 것은 "시간이 더 있으면" 에 이름을 적는다.
  안 한 것을 의도적으로 안 했다고 쓰면 판단이 되고, 침묵하면 모르는 게 된다
- **안 할 것** — 남은 시간에 못 하는 것을 붙잡으면 다른 게 무너진다

## 보고 형식

**에이전트 원문이 먼저 온다.** 내 정리는 그 뒤에 붙이고, 원문 안에 섞지 않는다.

```
■ 판정
   에이전트가 쓴 말 그대로. 등급·결론을 내 말로 바꾸지 않는다

■ 탈락 사유 · 감점 항목
   보고서 원문 순서 그대로. 통과 요소를 앞으로 끌어올리지 않는다

■ 돌린 조건
   회사 프로필 (파일명 / "없음 — 기본 가중치")
   요구사항 원문을 넘겼는지
   에이전트를 몇 번째로 띄운 것인지

■ 남은 시간 배분 (사용자와 정한 것)
   지금 고칠 것 / README 로 옮길 것 / 안 할 것
```

- **통과 요소만 모은 항목을 만들지 않는다.** 잘한 것을 앞에 놓으면 판정이 무해해 보인다
- 지적이 틀렸다고 판단되면 **원문을 옮긴 뒤 별도 항목으로** 적고, 근거 파일을 함께 댄다.
  근거를 확인하지 않았으면 반박을 적지 않는다
- 에이전트를 띄우지 못했으면 **띄우지 못했다고 적는다.** 내 판단으로 대신 채우지 않는다

## 언제 돌리나

- 제출 **2시간 전** 한 번. 고칠 시간이 남아 있는 시점
- `/assignment-submit` 은 그 뒤에 돈다. 순서가 반대면 고치고 나서 clean clone 검증을 못 한다

두 번 이상 돌릴 거면 **매번 새 에이전트**로 띄운다. 같은 에이전트에 이어 물으면
앞 판단에 끌려간다.
