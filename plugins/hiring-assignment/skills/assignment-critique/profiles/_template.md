# 회사 프로필 — <회사명>

> `assignment-critic` 에 실어 주는 채점표다. **절차는 에이전트가 갖고 있고 여기엔 가중치만 적는다.**
>
> 채우는 시점: **과제를 받은 직후.** 제출 안내를 읽는 그 자리에서 채운다.
> 나중에 채우려 하면 안내 문서를 다시 안 읽고 기억으로 쓰게 되고, 그러면 추정이 확정으로 섞인다.
>
> **확정도를 반드시 표기한다.**
> `[확정]` = 제출 안내·JD 원문에 있는 말. 원문을 그대로 인용한다
> `[추정]` = 블로그·발표·공고에서 유추한 것. 근거 링크를 같이 적는다
> **빈칸은 비워 둔다.** 채워야 할 것 같아서 추측으로 메우면 채점표가 오염된다.

---

## 1. 제출 안내 원문에서 뽑은 것 `[확정]`

안내 문서에 **적혀 있는 그대로** 옮긴다. 요약하지 않는다.

- 평가 기준으로 명시된 것:
  - (예) `[확정]` "요구사항 구현 완성도를 가장 중요하게 봅니다"
- 명시적으로 **보지 않는다**고 한 것:
  - (예) `[확정]` "UI 디테일은 평가하지 않습니다"
- 제출물에 포함하라고 한 것: (`.git` / 문서 / 스크린샷 / 회고)
- 제한 시간과 그 해석: (엄수인지 권장인지)
- 금지 사항: (라이브러리 추가 / 외부 공개 / 기존 코드 수정 범위)

## 2. 과제의 형태 `[확정]`

| 항목 | 값 |
|---|---|
| 기존 코드 개선인가 백지인가 | |
| 기존 코드가 있으면 그 저장소의 관례 | (주석 밀도 · 아키텍처 패턴 · 서식) |
| 요구사항 개수 | |
| 성능·접근성 요구가 명시됐는지 | |
| 문서 산출물 요구 | |

**기존 코드가 있는 과제에서 그 관례를 무시하는 것은 그 자체로 감점이다.**
내 취향의 구조를 얹기 전에 이 칸을 먼저 채운다.

## 3. 기술 스택 `[확정]` / 성향 `[추정]`

- JD 에 적힌 스택: `[확정]`
- 그중 이 과제에서 쓸 수 있는 것:
- 팀이 공개적으로 쓴다고 밝힌 것: `[추정]` + 근거 링크
- 쓰면 안 되는 것: (금지 명시가 있으면 `[확정]`, 없으면 적지 않는다)

## 4. 가중치 조정

기본값을 **덮어쓸 근거가 있는 축만** 적는다. 근거는 1절에서 인용한 원문이어야 한다.

| 축 | 기본 | 이 회사 | 확정도 | 근거 |
|---|---|---|---|---|
| 요구사항 완수 | 최우선 | | | |
| 실패 경로 처리 | 높음 | | | |
| 구조 강제 | 중간 | | | |
| 테스트 선택 | 중간 | | | |
| 문서 | 중간 | | | |
| 커밋 히스토리 | 낮음 | | | |
| 성능 계측 | — | | | |
| 접근성 | — | | | |

## 5. 지난 회차에서 감점된 것

같은 회사를 다시 지원하는 경우에만. 없으면 절 전체를 비운다.

## 6. 채우지 못한 칸

**비운 칸을 여기 나열한다.** 에이전트가 기본값으로 처리할 축이 무엇인지 알아야
"프로필에 있으니 이게 기준이겠지" 하는 오해가 안 생긴다.

## 어떻게 쓰나

```
Agent(subagent_type: "assignment-critic", prompt: """
<이 파일 내용을 그대로 붙인다>

---
평가 대상: <저장소 경로>
""")
```

프로필이 없으면 붙이지 않는다. 에이전트가 기본 가중치로 돌리고 그 사실을 보고서에 적는다.
